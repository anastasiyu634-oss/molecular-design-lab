# Molecular Design Lab v4.9.2

Локальный исследовательский сайт на Python / Streamlit. Наиболее заметное изменение — **понятный запуск докинга по выбранному участку связывания**, без ручной конвертации SDF/PDB/PDBQT.


## Исправление v4.9.2 — точная привязка координат атомов

В v4.9.1 обнаружена критическая ошибка сопоставления исходных и восстановленных
атомов при минимизации: координаты сохранялись по идентификатору остатка,
без имени атома. В v4.9.2 учитываются **цепь, номер/вставка остатка,
название остатка и имя атома**. Добавлена проверка повторяющихся атомов.

Это устраняет один программный источник искусственно больших смещений исходных
атомов. Оно **не гарантирует** подготовку конкретной PDB-структуры: другие
проблемы отсутствующих атомов и неверной связности остаются предметом проверки.

Для обновления v4.9.1 замени только `receptor_geometry.py`; `.venv` и `bin/vina.exe`
сохрани. Перезапусти Streamlit, затем выполни один контрольный расчёт и проверь
диагностику. Не ослабляй пороги смещения, не удаляй проблемные остатки.

## Обновление v4.9.1 — диагностика и геометрия рецептора

Проблема, зарегистрированная на `1A52`: `LEU A:539`/`A:541` имеют неполные тяжёлые атомы; `A:330`/`A:501` содержат альтернативные положения; после PDBFixer Meeko/RDKit сообщает о ложной или реальной недопустимой связности в районе `LEU A:544`. Источник — журнал, полученный на компьютере пользователя. **Успешный докинг с 1A52 пока не подтверждён.**

Изменения:

- Перед подготовкой выбирается один согласованный вариант альтернативных положений в каждом остатке по суммарной заселённости (occupancy). Выбранные значения фиксируются в техническом отчёте, исходный загруженный файл не изменяется.
- После достраивания тяжёлых атомов PDBFixer запускается сдержанная оптимизация геометрии OpenMM: исходные тяжёлые атомы удерживаются гармоническими ограничениями, а восстановленным атомам разрешается устранить пересечения. Если геометрия слишком сильно меняет исходные позиции или остаются очевидные столкновения, подготовка останавливается.
- Результат помечается как **модель с восстановленными координатами**. Запрещено молча удалять остатки или игнорировать ошибки шаблонов Meeko. Не используем `--allow_bad_res`, `--delete_bad_res` и `--forgive_extra_bonds` как обход проверки.
- При успешном докинге в технических данных показываются выбор альтернативных положений, число восстановленных атомов, RMSD/максимальное смещение наблюдаемых тяжёлых атомов.

Новая установка библиотек не нужна, если `requirements-repair.txt` уже был установлен: PDBFixer использует OpenMM. Для обновления v4.9 просто замени файлы `docking_runner.py`, `automatic_docking.py`, `docking_ui.py`, добавь `receptor_geometry.py` и при желании обнови этот README. Сохрани `.venv` и `bin/vina.exe`.

**Границы проверки:** код и искусственные unit-тесты прошли; в нашей среде нет PDBFixer/OpenMM и недоступен исходный mmCIF `1A52` с сервера, поэтому ни полноценная минимизация, ни сквозной докинг этого комплекса **не проверены**. Даже при получении PDBQT требуется научная валидация положения восстановленных атомов, протонирования, сетки и контрольный редокинг известного лиганда. Это исправление — консервативная попытка решить конкретную ошибку, не гарантия успешного докинга.

## Что изменилось

- **Нет значения `None` в таблице контактов.** Когда расстояние по ProLIF не рассчитано, отображается `—`. Это не нулевая дистанция и не отсутствие любых контактов.
- **Область связывания отделена от выбора белковой цепи.** При наличии экспериментального лиганда можно выбрать его участок. Если подходящих участков несколько, они показаны по PDB-кодам лиганда, цепи и номеру. Также есть вариант «Указать другую область по аминокислотам» (например, `GLU353, HIS524`). Для единственного участка он уже выбран по умолчанию.
- **Для запуска не требуется предварительно нажимать «Построить конформер».** Сайт создаёт 3D-молекулу из SMILES при нажатии **«Запустить докинг»**, готовит рецептор и вызывает AutoDock Vina.
- **Подготовка белка автоматизирована, но не скрывает ошибки химии.** Сначала Meeko, затем при наличии — альтернативное чтение через ProDy. Если оба пути не работают, допускается пробный PDBFixer, восстанавливающий недостающие атомы. Он не удаляет нераспознанные остатки. Если и после этого рецептор химически некорректен, докинг останавливается без фиктивного результата. Любые добавленные атомы помечаются как *смоделированные*; для серьёзной работы требуется проверка геометрии и контрольный редокинг.
- **Технические настройки, вручную подготовленный PDBQT и журналы** находятся в раскрывающихся блоках, не мешающих обычному пользователю.

Важно: участок связывания — это не номер цепи. Наш выбор по PDB ограничивается известными областями около экспериментальных лигандов; сайт **пока не ищет все неизвестные карманы белка**. Можно дополнительно задать участок через аминокислоты, но это пользовательская гипотеза, не автоматическое предсказание.

## Как обновить работающую v4.8

Останови Streamlit (`Ctrl+C`), распакуй архив `Molecular_Design_Lab_v4_9_update.zip` и замени содержимое в папке текущего проекта. Не удаляй `.venv` и `bin/vina.exe`.

Запусти из папки с `app.py`:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Для полного автоматического каскада подготовительных методов, если ProDy/PDBFixer ещё не установлены:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-repair.txt
```

pymanager exec -V:3.11 -m venv .venv

.\.venv\Scripts\python.exe -m pip install -r requirements-repair.txt

## Порядок работы

1. **Исследование комплексов:** загрузи один или несколько PDB, например `3ERT`, определи связанный лиганд и при желании рассчитай ProLIF.
2. **Фармакофор и дизайн:** попробуй выделить химические признаки. Созданный BRICS-кандидат может быть перенесён в раздел докинга, однако **BRICS ещё не оптимизирует его по фармакофору**.
3. **Докинг:** выбери молекулу, структуру белка и **область связывания** (по известному лиганду или аминокислотам); нажми **«Запустить докинг»**. Все технические шаги — внутри.
4. При успешном расчёте увидишь оценки Vina и 3D-модель позы. При ошибке увидишь краткое объяснение, а не выдуманный результат; журнал доступен в «Технических подробностях».

### Что проверить с 3ERT

В `3ERT` известный ориентир — экспериментальный лиганд `OHT`. Его участок может быть выбран автоматически. Но **это не устраняет химические проблемы атомной модели**. В прошлом Meeko отклонил несколько остатков в этой структуре, включая `PRO A:552`. Поэтому запуск на `3ERT` всё ещё может остановиться. Переход на иной режим чтения PDB или восстановление отдельных атомов не обязательно устраняет ошибочные межостаточные связи. При отказе надо проверить PDB-модель или выбрать другой хорошо подготовленный комплекс той же мишени / проверенный PDBQT.

### Ошибка `NotFoundError: removeChild`

Это отдельный сбой отображения Streamlit/React, не химического расчёта. Если он сохраняется, отключи автоматический перевод страницы `localhost:8501` и расширения, изменяющие HTML, затем перезагрузи страницу без кэша `Ctrl+F5`. **Мы не считаем эту ошибку исправленной**, пока не проверим браузер. Содержимое расчёта обычно не связано с ней.

## Научные ограничения

- Оценка Vina — результат скоринговой функции, **не** измеренная энергия и **не** доказательство ингибирования.
- Отсутствие ошибки в Meeko не доказывает, что все протонирования, заряды, неканонические остатки и химия кармана корректны.
- Если PDBFixer восстановил атомы, результат предварителен и требует валидации; нельзя автоматически удалять проблемные остатки ради успеха докинга.
- Для оценки качества протокола следует выполнить редокинг экспериментального лиганда, проверить RMSD, положение сетки и воспроизводимость.
